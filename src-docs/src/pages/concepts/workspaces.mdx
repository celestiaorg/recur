# Workspaces

A **workspace** is the unit of work in Recur: a checkout plus the UI around it (chat, editor, terminal, Observatory, PRs).

## Working copy vs task workspaces

- **Working copy**: your project's real git checkout. Titlebar actions are **Commit**, **Update**, and **Push**. It cannot Merge or open a PR (it *is* the project tree), and it does not offer Autopilot mode.
- **Task workspaces**: isolated git worktrees on their own branches. Run any [chat mode](/concepts/modes) here without colliding with other tasks.

## Layout

A workspace shows the agent chat on the left, one view at a time with the terminal in the center (or wherever you [place it](#layout)), and a right panel for the lists you open files from: files, search, artifacts and so on. The last icon in the toolbar (`⌥⌘⇧B`) shows and hides the right panel, and the pin beside it switches it between floating and docked.

The buttons at the front of the toolbar's center group pick the center's view: **Plan**, **Editor**, **Review** and, once the workspace has one, **Pull request**. A button switches to its view and does nothing when it is already showing. The Plan button counts the plan's remaining steps. A link to the plan in the chat switches the center to it.

The **Artifacts** panel is on the right by default, beside the chat: opening an artifact from it opens the artifact as an editor tab while the list stays in view, and you can drag a row into the chat to @-mention it. Its icon counts the artifacts that arrived since you last looked at the list.

The left column holds the chat and the **Findings** panel, one at a time, switched by their icons at the left of the toolbar; the first icon (`⌥⌘B`) hides and shows the column. Findings are on the left so you can read one beside the code it is about: a link to a finding in the chat opens the panel and the finding's file. The Findings icon counts the open ones. Other panels you place on the left in Settings show their icons there too.

The right panel is either floating or docked. This is one setting for every workspace:

- **Floating** (the default): the panel takes no column, and the toolbar does not show its icons. The show button slides it out from the right edge, over the editor. Its icons come out with it, in the toolbar over it where they are when docked, to switch between files, search and the rest; the editor's toolbar buttons move over so they stay in view. It stays open while you work in it or in the chat, so you can open one file after another from it. It closes when you click in the editor column, click the show button again or press `Esc`. Drag its left edge to resize it; it remembers that width apart from the docked one. Project search, find references and the problems list open in it too. The editor keeps its width and the chat takes the rest of the window; drag the editor's left edge to resize it.
- **Docked**: the panel is a column beside the editor that stays until you hide it (docking it shows it), and its icons sit in the toolbar over it. The chat has its own width and the editor takes the rest.

Switch in **Settings → Code editor → Code panels → Right panel**, with `⌥⌘J`, the pin button in the toolbar, or **View → Float Right Panel**. In a narrow window the panels stack either way.

The Terminal button in the toolbar (``⌃` ``) shows and hides the terminal, and the chevron beside it opens a menu of where the terminal shows:

- **Below the editor** (the default): under the center column.
- **Below the chat and editor**: one dock under the chat and the editor. The right panel keeps its full height, beside the dock when docked and over it when floating. A floating right panel stops at its top edge.
- **In place of the editor**: the terminal is a view of the center column, like the editor or the review. The Terminal button switches to it, and the other views' buttons switch away; the shells keep running. ``⌃` `` switches to the terminal and back to the view it covered, and `⌥⌘E` switches between the terminal and the editor.
- **Beside the editor**: the editor and the terminal side by side, with a split you can drag.

Picking a placement shows the terminal there and is remembered for that workspace. Workspaces you have not picked one for follow **Settings → Code editor → Code panels → Terminal**; **Use default** in the menu puts a workspace back on it. Below the editor or the chat, drag the terminal's top edge to resize it (the two share one height). In a narrow window the full-width terminal sits under the stacked panels. ``⌃⇧` `` maximizes the terminal in every placement.

Once a workspace has a pull request, a pull request button appears beside the review button in the toolbar, with a badge for failing checks. It shows the pull request where the editor is, with its own tabs in the row under the toolbar: **Overview** (the conversation, led by the pull request's state, title, people and attention labels), **Commits**, **Files changed** and **Checks**. Everything you can do to the pull request is in the workspace, so there is no separate page to switch to. See [Pull requests](/concepts/pull-requests).

## Isolation & parallelism

- Separate worktrees, so parallel workspaces never share a dirty tree
- Setup, teardown, named Runs, and env live in committed [`.recur/project.toml`](/concepts/project-toml)
- Inside a workspace, open multiple agent chats, each with its own mode

[Child workspaces](/concepts/modes#child-workspaces) started from an Agent chat or a [workflow](/concepts/workflows) nest under their parent in the sidebar. Use [Inbox](/concepts/inbox) to find work across projects, or [Schedules](/concepts/schedules) to start tasks automatically while Recur is open.

## Landing the work

- **Hand-driven** workspaces (no workflow engaged) can **Merge** onto the base: pushed to `origin/<base>` when the project has a remote (local `<base>` fast-forwards when it can), otherwise merged into the local branch. Merge is hidden when GitHub branch protection requires a pull request.
- Workflows that end in a PR open a GitHub PR, or a Local PR when the project's **Open PRs on GitHub** setting is off. Other workflows stop after review and fixes. See [Pull requests](/concepts/pull-requests).
- Merge and PR creation refuse to run while there are uncommitted changes.

## Open a project or file

- **File → Open…** (`⌥⌘O`), `recur .`, or `recur <path>` finds or creates the project and opens its Working copy
- Files outside any project open as absolute-path tabs; they do not create a project
- **Open In…** (`⌘O`) opens the worktree in Finder, Terminal, and other apps
- To keep a project out of the sidebar, turn on **Hide from sidebar** in its project settings. The eye button in the Projects header shows hidden projects again

## Import from Conductor

On a Mac with [Conductor](https://conductor.build) data, **File → Import Conductor Workspaces…** brings its workspaces into Recur:

- Every workspace Conductor has not archived, whose worktree is still on disk, becomes a Recur workspace. Archived ones are skipped
- Worktrees stay where they are, on the same branch. Recur does not move them, re-create them, or run the project's setup command
- A repository Recur does not know yet is added as a project in the **Imported** sidebar group
- A project the import adds gets Conductor's setup, run, and archive scripts as its `.recur/project.toml` (setup command, a `dev` run, and teardown command), unless the repository already has one. `$CONDUCTOR_ROOT_PATH`, `$CONDUCTOR_WORKSPACE_PATH`, and `$CONDUCTOR_PORT` become `$RECUR_ROOT`, `$RECUR_WORKTREE`, and `$RECUR_PORT`; a script using another Conductor variable is skipped
- Each visible Conductor chat becomes a chat tab with its transcript. The first message you send starts a new agent session that receives the earlier conversation, because Conductor's own agent sessions cannot be resumed
- Running the import again skips worktrees already in Recur

Conductor Cloud workspaces run on Conductor's servers, so the import cannot see them. Move each one to your Mac first: in Conductor, right-click it and choose **Transfer to local**, then run the import. Do this before Conductor Cloud turns read-only on November 13, 2026.

## Editor

- **Quick Open** (`⌘P`) finds files; **Go to Symbol** (`⌘⇧O`) jumps to a symbol
- **Find** (`⌘F`, then `⌘G` / `⌘⇧G` for next and previous) is under Edit → Find; **Go to Line** (`⌘⌥G`) is under Navigate
- Language servers supply completions and diagnostics. Recur installs most shipped servers on first use; others, such as Solidity's, must be on your `PATH`
- Preview Markdown, HTML, SVG, Mermaid, and PDF files. `⌘F` searches inside Markdown, HTML, SVG, and Mermaid previews
- Uncommitted work is the review's **Uncommitted** tab, where you check files into a commit and write its message. See [Commit from the review](/concepts/review#commit-from-the-review)
- The file explorer shows the files changed since the base branch, or all files. Each changed file carries its `+N −M`, the same counts as the review, and each folder the total under it
- **Filter files** at the top of the explorer keeps the files whose name or path contains what you type, in the scope showing. In all files it also finds files in folders you have not opened. `Esc` clears it, and the tree comes back as you left it
- Drag files in the explorer to move them
- `⌘F` in a terminal tab opens a find panel

## What persists

Coming back to Recur restores the last workspace, active chat tab, chat UI state, and terminal sessions (with replay).

For per-turn diffs and restoring earlier work, see [Review & checkpoints](/concepts/review).

## Pointing the agent

Mention files, folders, and terminals with `@`, drag files into chat, and tag Diff or editor selections with **⌘L** so the agent sees the exact context. See [Chat context](/concepts/chat-context).
