# Inbox

Open **Inbox** in the sidebar to see work across your projects, including scheduled runs and agent tasks.

| Group | What to look for |
| --- | --- |
| **Needs you** | Questions, permissions, or other work waiting for your attention |
| **Working** | Tasks with work in progress |
| **Pick up** | Work you can return to or inspect next |

Filter by project, choose a group, or enable **Unread** to narrow the list. The selected workspace's overview sits beside the list (the first one when you arrive): what arrived since you last looked, what it needs from you (answer questions, allow or deny permissions, and approve plans right there), open review findings (**Fix** asks its agent to address them), failing checks (**Fix checks** sends them to its agent), what it is doing now (**Stop** interrupts it), its latest reply, plan progress and changed files. Finished work shows the next step: merge or mark ready its PR, or open a PR. Use ↑ and ↓ to move between workspaces. Opening a workspace's overview marks it read; **Mark unread** (⇧⌘U) brings its dot back so it stays under **Unread**. Drag the edge between the list and the overview to resize them; the width is remembered, and a wide list shows each workspace's project, plan progress, diff and age again. In a narrow window, click a workspace to open its overview and press Esc to close it. **Open workspace** (or Enter, a double-click, or ⌘-click) takes you into it to answer its question, inspect the diff, or continue chatting. While an overview is open, Ask Recur knows which workspace you are looking at: ask "how is this going?" or "tell it to also cover the 502 path" and it reads or messages that workspace.

Read status tracks what you have seen. Marking an item read does not answer a pending question, resolve findings, or finish its task.

The **Ask Recur** panel lets you run your work from Inbox. Ask what needs you or how a task is going: it can look into any workspace's latest reply, plan, changed files, PR checks and recent steps. Type `@` to point it at a specific workspace or project. Have it start a workspace in any project (or a new project: it creates the folder as a fresh git repo, or clones one, in the [new projects folder](/reference/settings) unless you name a path), send instructions to a running or idle agent, or pass along your answer to an agent's question. When a workspace it started or sent instructions to finishes, Ask Recur reports back in that chat, and again if its PR checks start failing. It does not edit files itself or approve permissions; workspace agents do the work. For recurring work, create a [schedule](/concepts/schedules); each run gets its own workspace to inspect.
