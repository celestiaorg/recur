# Providers

Open **Settings → Providers** to turn providers on or off, check their status, and configure authentication. Pick a model per chat in the composer, and set each mode's default under **Settings → Models**.

| Provider | Setup |
| --- | --- |
| **Claude Code** | Install Claude Code and run `claude auth login`. Recur uses that login and shows its status in Providers. |
| **Cursor** | Click **Connect** in Providers and sign in through your browser. Recur runs Cursor's agent through a local bridge it downloads when needed. The model list, including Grok and other Cursor models, comes from your Cursor account. |
| **ChatGPT account** | Under **OpenAI**, click **Continue with ChatGPT** and sign in through your browser, or with a device code. Uses your ChatGPT plan directly. Recur runs the coding tools, so no Codex install or API key is needed. |
| **Codex** | Install the Codex CLI (`brew install --cask codex`) or set its path. Under **OpenAI → Codex runtime**, sign in with ChatGPT, reuse your login from `codex login`, or add an API key. The model list comes from Codex. |
| **Antigravity** | Install the Antigravity CLI (`agy`) from [antigravity.google](https://antigravity.google), then run `agy` in a terminal and sign in with Google. The model list comes from Antigravity. |
| **OpenCode** | Install OpenCode from [opencode.ai](https://opencode.ai), then run `opencode auth login`. The model list comes from OpenCode and the providers you signed in to there. |
| **Compatible endpoint** | Add a provider with a base URL, model IDs, and an API key when the server requires one. |

## Compatible endpoints and local models

The compatible provider sends requests to **`{base URL}/v1/responses`**. The endpoint must support the Responses API and the tool calls needed for coding. A server that only implements Chat Completions is not enough. Recur runs the coding tools itself, inside the workspace's worktree.

Choose **Add provider**, then a preset (**OpenAI**, **OpenRouter**, **Groq**) or **Custom**. Enter the base URL without a trailing slash and add at least one model ID supported by that server. Extra headers are available for endpoints that require them. **Test** sends a small request to check the connection.

For a local server such as Ollama, use Custom with your own provider slug such as `local-ollama` (the slug `ollama` is reserved), the server address (for example `http://localhost:11434`), and an installed model ID. The server version and model must support the Responses API and tools. Leave the API key empty when the endpoint does not require one.

## Where work runs

Repositories, worktrees, file edits, and tool processes run on your machine. Cloud providers receive the prompts and code context sent to them. A local inference server can keep model requests local too. Recur does not require a hosted checkout.

## Where credentials are stored

API keys and other secrets you enter in Settings are kept in your system's credential store, not in Recur's database:

- **macOS**: the Keychain, under the service name **Recur**.
- **Linux**: the Secret Service keyring, through `secret-tool`.

If that store is missing or fails, for example on Linux without `secret-tool`, Recur keeps them in a `secrets.json` file in its data folder that only your user can read. The next time saving to the credential store works, the secrets move there and the file is removed.

This covers the Cursor, Codex and Linear keys, compatible endpoint API keys and headers, MCP server headers and environment, and the values bundles store under **Settings → Integrations**. Keys saved by versions before 0.7.0 were moved out of the database. `recur config` cannot read or set credentials.

Sign-ins are separate. A ChatGPT account sign-in is a file (`chatgpt-auth.json`) in Recur's data folder that only your user can read, and a Codex sign-in through Recur is in Recur's own Codex folder there. Connecting Cursor also keeps a session file there for plan usage. Claude Code, Antigravity and OpenCode keep their own logins.

## Questions and permissions

Agents can ask questions and request tool permissions in chat. Answer there to continue the work. **Settings → Providers → Bypass tool permissions** skips permission prompts. Recur also asks before an agent starts a [background process](/concepts/background#permission) or changes a [schedule](/concepts/schedules#agents-can-manage-schedules), unless that setting is on. Installing a bundle always asks. Use [Inbox](/concepts/inbox) to find tasks waiting for you across projects.
