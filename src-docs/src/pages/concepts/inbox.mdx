# Inbox

Open **Inbox** in the sidebar (`⌥⌘1`) to see work across your projects, including scheduled runs and agent tasks.

## Groups

| Group | What to look for |
| --- | --- |
| **Needs you** | Unread replies, questions, permissions, or other work waiting for your attention |
| **Working** | Tasks with work in progress |
| **Pick up** | Work you can return to or inspect next |

Filter by project, choose a group, or enable **Unread** to narrow the list.

## Move around

| Do this | How |
| --- | --- |
| Move between workspaces | `↑` `↓` |
| Open the selected workspace | **Open workspace**, `Enter`, `⌘O`, a double-click, or a `⌘`-click |
| Mark unread or read | **Mark unread** / **Mark read**, or `⇧⌘U` |
| Close the overview in a narrow window | `Esc` |

Open a workspace to answer its question, inspect the diff, or continue chatting.

## The overview

The selected workspace's overview sits beside the list. When you arrive, it is the first workspace. It updates live as the agent works, and shows:

- what arrived since you last looked
- what it needs from you: answer questions, allow or deny permissions, and approve plans right there
- open review findings: **Fix** asks its agent to address them
- failing checks: **Fix checks** sends them to its agent
- what it is doing now: **Stop** interrupts it
- its latest reply
- plan progress
- changed files: **Review** opens the diff in the workspace

Finished work shows the next step: merge its PR or mark it ready for review, or open a PR.

Drag the edge between the list and the overview to resize them. The width is remembered, and a wide list shows each workspace's project, plan progress, diff and age again. In a narrow window, click a workspace to open its overview.

## Read and unread

Opening a workspace's overview marks it read. **Mark unread** brings its dot back so it stays under **Unread**.

Read status tracks what you have seen. Marking an item read does not answer a pending question, resolve findings, or finish its task.

## Ask Recur

The **Ask Recur** panel lets you run your work from Inbox.

### What it can do

- **Tell you what needs you** or how a task is going. It can look into any workspace's latest reply, plan, changed files, PR checks and recent steps.
- **Start a workspace** in any project.
- **Create a project.** It creates the folder as a fresh git repo, or clones one, in the [new projects folder](/reference/settings#general) unless you name a path.
- **Send instructions** to a running or idle agent.
- **Pass along your answer** to an agent's question. It does not answer one on its own judgment.
- **Report back.** When a workspace it started or sent instructions to finishes, it reports in that chat, and again if the workspace's PR checks start failing.

Type `@` to point it at a specific workspace or project. While an overview is open, Ask Recur knows which workspace you are looking at: ask "how is this going?" or "tell it to also cover the 502 path" and it reads or messages that workspace.

### What it cannot do

Ask Recur does not edit files or run commands itself; workspace agents do the work. It cannot approve permissions, merge, archive, or open PRs. Those stay with you, in the overview or the workspace.

For recurring work, create a [schedule](/concepts/schedules). Each run gets its own workspace to inspect.
