# Chat modes

A mode belongs to the chat, not the workspace. Pick it from the mode menu in the composer, switch it anytime, and run several chats in different modes in the same workspace.

| Mode | Color | What it does |
| --- | --- | --- |
| **Ask** | Emerald | Answer questions and write reports. Read-only |
| **Plan** | Yellow | Investigate and produce a plan. Read-only |
| **Agent** | Cyan | Read and edit files, with you in the loop |
| **Review** | Indigo | Review the diff and file findings. Read-only |
| **Autopilot** | Amber | Run a [workflow](/concepts/workflows): a team of specialist agents under a policy |

You don't need to use the modes in order. Start in Agent, or run an Ask chat beside an Autopilot chat.

In Autopilot mode the composer swaps its model picker for a **Workflow** picker and a **Policy** picker. Both are pinned once the workflow starts. The [Working copy](/concepts/workspaces) offers every mode except Autopilot. Pull request chats offer Ask, Plan, and Review.

## Models per mode

**Settings → Models** sets the default model for each mode. A new chat starts on its mode's default; pick any model in the composer to override it. Workflow roles use the default for their role's mode, so the Coder uses the Agent model and the Reviewer uses the Review model.

## Child workspaces

An Agent chat can hand a subtask to a **child workspace**: its own worktree and branch, started from the parent's branch, with its own chat. The parent keeps working and gets a report when the child finishes. It can then merge the child's commits into its own branch or archive the child.

- The parent can message a child. A running child is steered mid-turn; a finished child that is not yet merged or archived starts a new turn and reports back again.
- Children appear nested under their parent in the sidebar. Open one to watch or chat with it directly.
- Children do not create children of their own.
- **Settings → Models → Child workspace model** chooses whether a child copies the calling chat's model or uses its mode's default.

Workflows use child workspaces for [parallel plan steps](/concepts/workflows#parallel-child-workspaces).

## Simplify

**Simplify** is on by default for new chats. It asks the agent to reuse existing code, make smaller changes, and avoid unnecessary abstractions. It applies to Agent and Plan chats and to workflow coding roles, not to Ask or Review.

Toggle it per chat in the composer. **Settings → General** sets the default for new chats. Use `/simplify-review` or `/simplify-audit` when you want a review of unnecessary complexity.

## Messages while an agent runs

Sending while an agent is working either **steers** the running turn or **queues** the message until the turn ends. By default `⏎` steers and `⌘⏎` queues. Turn on **Settings → Agents → Queue follow-ups while an agent runs** to swap them.
