# Follow-ups

Open items that are known but not scheduled.

- [ ] **The icon generator reads the website demo.** `crates/ui/assets/icons/generate.mjs` reads `src-web/demo` (`src/lib/icons.ts`, `src/lib/lucide-icons.ts`, which the demo no longer has, and `ProviderIcon.svelte`). Make the Rust assets the source of truth or retarget it.
- [ ] **mr-boxington in CI.** Local dev builds go through `mbx` (see `mise.toml`); CI still uses `Swatinem/rust-cache`. Try `jdx/mr-boxington-action@v1` with `mbx clippy` / `mbx test` in `.github/workflows/ci.yml` so pushes to main fill a shared cache and PRs restore from it.
- [ ] **`fetch` in the TypeScript Worker.** The JavaScriptCore Worker (`crates/bundles/src/js.rs`) has no `fetch`, nor `Headers` / `Request` / `Response` / `Blob` or `crypto.subtle` (documented in `docs/bundles.md`). Adding it means a native that runs the request on `recur-http` and resolves a promise from the worker loop, plus those classes in the prelude. No shipped bundle needs it.
- [ ] **Vim on the editor model, not CodeMirror 5.** `crates/editor/src/vim/` is a port of `@replit/codemirror-vim`, which runs vim.js on a CodeMirror 5 adapter; `vim/cm.rs` ports that adapter. Motions, operators and ex commands work in CM5 (line, char) positions with deliberate out-of-range arithmetic (`ch = -1`, `INF`, a line past the end) that `cm.rs` clips into offsets; `CurOp` / `op_begin` / `op_end` mimic CM5's event batching, which `.` repeat and macro recording depend on; search cursors, scroll geometry and bookmarks are in the same terms. Rewriting vim onto `EditorState` offsets, `SelectionRange` and transactions would drop the adapter, but it is a rewrite of each motion and operator: build a much broader vim test suite first (only a handful of integration tests in `crates/editor/tests/view.rs` cover about 11.6k lines). Also: in replace mode (`R`) Backspace deletes instead of only moving left, because the editor keymap handles it before vim.
