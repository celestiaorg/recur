# Changelog

Notable changes in each Recur release. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/). Downloads for every version are on [GitHub releases](https://github.com/celestiaorg/recur/releases).

## [0.8.0](https://github.com/celestiaorg/recur/releases/tag/v0.8.0) - 2026-11-24

### Added

- The right panel floats by default: it takes no column, and opens as a flyout that slides out from the right edge, over the editor or the review, when you click the show button at the end of the toolbar (⌥⌘⇧B). Its icons show in the toolbar only while it is out. It stays open while you pick from it or type in the chat, and closes when you click in the editor column or press `Esc`. Drag its left edge to resize it; its width is remembered apart from the docked one. The chat takes the width the editor leaves, so drag the editor's left edge to resize it. Switch between floating and docked for every workspace in **Settings → Code editor → Code panels**, with ⌥⌘J (Ctrl+Alt+J on Linux), the pin button in the toolbar or **View → Float Right Panel**.
- A workspace with a pull request has a pull request button beside the review button in the toolbar. It shows the pull request where the editor is, with its Overview (the conversation), Commits, Files changed and Checks tabs in the row under the toolbar. The button's badge counts failing checks.
- Sidebar rows show whether a workspace's open pull request has failing, running or passed checks.
- The file explorer has a **Filter files** box, like the review's file list: type part of a name or path to narrow the tree to the matching files and their folders, in the changed files or in all files (where it also finds files in folders you have not opened). `Esc` clears it and the tree comes back as you left it, with the same folders open.
- The file explorer shows each changed file's `+N −M` beside its status letter, the same counts as the review, and each folder's total.
- The review's **Uncommitted** tab is editable: each text file's diff is the editor's diff view against `HEAD`, so you can fix code while you review what you are about to commit, with the cards still in one scrolling list. `⌘S` saves the file you are in, a dot marks unsaved cards, and a card and an editor tab of the same file show the same text. A file you edit there opens as a tab, so its unsaved edits stay when the card scrolls away, when you close the review and across restarts.
- The workspace toolbar's Terminal button has a menu (the chevron beside it) for where the terminal shows: below the editor, below the chat and editor (one dock under both), in place of the editor (a view like the review, switched to with the button or ⌃`), or beside the editor. The choice is remembered per workspace; workspaces without one follow the new **Settings → Code editor → Code panels → Terminal** default, and **Use default** in the menu goes back to it.
- **Ask Recur** in Inbox can now direct your work: start a workspace in any project, create a new project (a fresh git repo or a clone), send instructions to any workspace's agent, and relay your answers to agents' questions. It reports back when that work finishes, and can look into any workspace to tell you how a task is going. It still does not edit files or approve permissions.
- Agents can start a standalone workspace in another project by name when you ask them to.
- Mention a workspace or project with `@` in any chat, including Ask Recur, to give the agent its current state.
- Inbox shows the selected workspace's overview beside the list (the first one when you arrive) instead of leaving Inbox: what arrived since you last looked, its questions and permission requests (answer them right there), plan approval, open review findings (**Fix** sends them to the agent), failing checks (**Fix checks** sends them to the agent), what it is doing now (with **Stop**), its latest reply, plan progress and changed files. Finished work offers the next step: merge the PR, mark it ready, or open one. Ask Recur knows which workspace is open, so "this" and "it" mean that workspace and it can relay instructions to its agent. The overview updates live as the agent works. **Open workspace**, Enter, double-click or ⌘-click opens it. Drag the edge between the list and the overview to resize it; Inbox remembers the width, and a wide list brings back its project, plan, diff and age columns. **Mark unread** (⇧⌘U) flags a workspace to come back to.
- Ask Recur sees PR check results and tells you when checks start failing on a workspace it started or sent instructions to.
- Insights: a new view in the sidebar showing how your agents spent their time by week, month or year, with a year of daily agent hours, where the hours went, time lost, and per-model and per-command breakdowns.
- Antigravity and OpenCode as providers. Install the agent and sign in from a terminal, turn it on in **Settings → Providers**, and its models appear in the pickers.
- Agents in Agent mode can run long-lived processes (dev servers, watchers, long test runs) in a terminal tab you can see, with any provider. The workspace owns the process, so it keeps running across turns and model switches. When it exits on its own, the chat that started it gets a new turn with the exit code and the last lines of output. Background tabs show an activity icon: closing one hides it and leaves the process running, the activity count in the terminal dock lists hidden ones to reopen or stop, and the **Stop** button in the terminal dock stops it. With **Bypass Permissions** off, Recur asks before an agent starts one. Background processes stop when you quit Recur or archive the workspace; after a restart, the agent is told on its next turn which of its processes the quit stopped. Their output is also saved to a log file in the workspace's data folder.
- Agents can ask to check back later, with any provider: after a delay from 1 minute to 24 hours, the same chat gets a new turn with the agent's reason, shown as a "Check back in 10 min" row. While it waits, the bottom of the chat counts down ("Checking back in 0:42") with the reason. A chat has at most one pending check back, it still fires if Recur was closed when it came due, and closing the chat or archiving the workspace cancels it.
- Agents in Agent mode can create, list and delete scheduled prompts for their project. Schedules an agent creates show up in the Schedules view like your own. With **Bypass Permissions** off, Recur asks before an agent creates or deletes one. Ask and Plan chats can list schedules.
- Watch schedules: give a schedule a shell command, and every line it prints starts a run with those events appended to the prompt. Recur keeps the command running while it is open, restarts it if it exits, and queues events that arrive during a run into one follow-up run. The schedule row shows whether the command is watching, its last error, and its last event.
- Agents can create Watch schedules with `create_schedule`, and edit any of the project's schedules by passing its id. Recur shows you the command and asks before saving it.
- Workflows can run a command as a phase: `uses = "run"` runs something like `mise run check` in the worktree, and a failure can send the work back to the build phase with the command's output.
- Agents in Agent and Autopilot modes can install a bundle they wrote with the new `install_bundle` tool. Recur lints it first and asks you to approve every install, showing what it adds and anything that runs shell code. A `reload_bundles` tool reloads bundles and lists the installed workflows, roles, and policies.
- Drag a file or folder from the review's file list into the chat composer to @-mention it, or onto the terminal to insert its path, as from the file explorer.
- Drag an artifact from the Artifacts panel into the chat composer to @-mention it.
- A global **Conventional Commits** setting in Settings → Pull requests. Each project follows it unless the Project page (or `conventional_commits` in `.recur/project.toml`) turns it on or off for that repo.
- A PR with merge conflicts says so under its checks in the Conversation tab and lists the conflicting files, as GitHub does.

### Changed

- Run and Stop in a workspace's titlebar are one split button: it reads **Run dev** until the run starts, then **Stop dev**, and its menu still starts another run. With several runs going it reads **Stop** and asks which to stop.
- A workspace's titlebar no longer has a Remove button, which took a lot of its room. Remove a workspace from its row in the sidebar.
- A pull request that has a workspace now opens in that workspace instead of on a page of its own. Opening it from the dashboard, the Inbox, a notification, the sidebar, the command palette or a link in the chat selects the workspace and switches its center to the pull request view, so the chat, the files and the PR are in one place. A PR without a workspace still opens as a page, as does an older or closed PR of a workspace that has a newer one. **Create workspace** on that page takes you to the new workspace, on its pull request view.
- The pull request's state, number, title, people and attention labels, which led the PR page, lead its Overview tab in a workspace. Its branch is in the workspace's titlebar.
- The PR page's titlebar buttons have a home in the workspace. The workspace titlebar has the PR's next step (Ready for review, Fix checks, Queued, Conflicts or Blocked, or Merge), whatever the center shows. **View PR #N** switches the center to the pull request instead of leaving the workspace, and its menu has **Open in GitHub** and, new, **Convert to draft**. **Send back**, the pending comments chip and **Approve** / **Request changes** are at the right end of the pull request's tab row. Update with base, Pull, Push and Force push are the workspace's own, as before.
- The titlebar's **View PR** button shows the pull request's state with its icon and color (open, draft, in the merge queue, merged or closed), as the workspace's row in the sidebar does.
- Plan moved out of the side panels into the center column. It is a view like the editor, the review and the pull request, and its button leads the toolbar's center group (Plan, Editor, Review, Pull request, Terminal) with the remaining-steps badge its panel icon had. A link to the plan in the chat switches the center to it. It no longer has a side in **Settings → Code editor → Code panels**, and a saved side for it is ignored. Artifacts is a side panel on the right by default, beside the chat, so the list stays in view while an artifact you open shows as an editor tab. Findings stay a side panel, on the left by default, so a finding can be read beside its code.
- The editor, review and pull request buttons in the workspace toolbar switch to that view and do nothing when it is already showing; they no longer hide it on a second click. ⌥⌘E still hides and shows the editor, and ⌥⌘R still switches to the review and back.
- The separate "Terminal beside editor" toolbar button is gone: beside the editor is now one of the Terminal button's placements. Workspaces that had the terminal beside the editor keep it there.
- The editor's file tabs (and the review's Changes and Commits tabs) moved out of the toolbar into their own row over the editor, level with the chat tabs, so they have the editor's whole width. The toolbar keeps the icons.
- Source Control moved into the review as its **Uncommitted** tab, there while you have uncommitted work, and opening the review lands on it then. The review's file list gets a checkbox per file and folder for what goes into the commit (checking stages, unchecking unstages, a dash for a file staged only in part), discard on hover, in a diff's header and with **Discard all**, and the commit message box with AI generate and **Commit** (`⌘↵`) under it. Commit takes the checked files, or everything when nothing is checked. The Review button shows the uncommitted file count, the explorer's dirty count opens the tab, and the titlebar's **Commit** menu has **Review and commit…**. The Commits tab no longer lists uncommitted changes.
- Todos from every model (Claude, Cursor, Codex, and OpenAI-compatible) now land in the workspace's Plan panel as one shared checklist. They survive switching models or chat tabs, and your own edits to the list are kept.
- Claude, Cursor and Codex chats no longer start their own hidden background processes. Agents use Recur's background processes instead, so they show up in the terminal dock and keep running after the turn ends.
- A Plan made only of todos can be edited in the Plan panel without writing a summary first.
- When you expand a collapsed group of tool calls, the agent's text messages inside it always show in full, with no row to expand. Tool calls and thinking stay collapsed.
- Recur now needs Git 2.38 or newer. Older Git shows a "Git is too old" alert at launch. Rebase merges onto a remote branch need Git 2.40 or newer.
- The model picker lists providers in a column beside their models: pick a provider (or press Left and Right) to see just its models. Search still finds models across every provider.
- Live replies and thinking now appear a whole paragraph at a time, for every agent, instead of typing out word by word or in mid-paragraph chunks. Returning to a chat mid-reply shows the paragraphs finished so far.
- Queued follow-ups now send one at a time, each as its own turn, instead of folding into a single message. Steer, or put several requests in one queued message, to send them together.

### Removed

- The Source Control side panel, its icon and its side in **Settings → Code editor → Code panels**. Its lists, staging, discard and commit box are in the review's Uncommitted tab.

### Fixed

- Ask Recur can list your workspaces when there are many of them. With a hundred or so, the list was too long for the agent to read and showed an error instead of the workspace card.
- Ask Recur's extra chat tabs (beyond the first) can now look up your workspaces.
- Earlier Claude chats that stopped a background task now show a "Stopped task" row with the command that was stopped, instead of raw JSON.
- Copying a message you sent and pasting it into a chat or new workspace composer now brings its images and its file, skill and terminal chips along, not just the text.
- Claude Code chats older than about 30 days no longer fail with "No conversation found with session ID". Claude Code deletes old transcripts, so Recur now starts a fresh Claude session and passes along the chat history it keeps itself. Retry fixes chats that already show the error.
- Reload from disk, or discarding a tab and reopening it, now shows the file on disk. The editor used to bring back the unsaved text.
- The code editor no longer goes blank when the caret is next to a curly quote, accented letter, emoji or other special character. Pressing Enter just before one works again too, and so do Home and Cmd-Left on long lines that contain them.
- Typing your own answer on a question card works again. Clicking the answer field no longer moves focus back to the transcript.
- A leftover `REBASE_HEAD` from an earlier rebase no longer makes Recur show the Update button on an up-to-date branch or refuse with "a merge or rebase is already in progress".
- Folders with `...` in their name, like Next.js `[...nextauth]` routes, now open in the file tree, the editor and agent tools instead of failing with "path escapes root".
- A chat message that almost filled a line no longer gets a bubble with an empty second line.
- On the Schedules page, the status and next run columns line up whether or not a schedule has workspaces.
- Ask Recur's workspace summary says "1 needs you" instead of "1 need you".
- Files with merge conflicts are marked `!` in red in the file explorer, the review's Uncommitted tab and the status bar, and their folders turn red too. In the Uncommitted tab a conflicted file starts unchecked, so checking it marks it resolved.
- Merging a workspace into a remote branch such as `origin/main` no longer goes through your project folder. It works when your local `main` is out of date, has commits of its own, or has uncommitted changes, and your project folder stays on whatever branch it was on. Local `main` fast-forwards afterwards when it safely can.
- When an agent creates a standalone workspace, the chat shows a one-line "Created workspace" row with its title and an **Open** link to the new workspace, instead of the raw tool call and prompt.
- Starting several workspaces in one project at the same time no longer fails some of them with "failed to read .git/worktrees/…/commondir".
- A Claude spend or rate limit hit on a turn Claude started on its own (for example after a background task finished) now shows the usage-limit card with Retry instead of a plain reply.
- An Autopilot workflow stopped by a spend or rate limit now shows the usage-limit card with Retry in its chat, instead of a plain Maestro line.
- Auto-update now installs the latest release even when an older update was already downloaded and waiting for a restart. Previously Recur kept offering the older version until you restarted.

## [0.7.0](https://github.com/celestiaorg/recur/releases/tag/v0.7.0) - 2026-11-13

### Added

- The sidebar can group workspaces by status (In progress, including draft PRs; In review; Done; Closed) instead of by project, with each project's working copy in a Working copies section: use the new button next to **Add project**. Scheduled runs stay in the project view.
- Fable 5.2 in the Claude Code model picker. Mythos 5.2 appears automatically on accounts with access.
- The New project dialog has a **Group** picker, so a project can go straight into a sidebar group when you add it.
- The workspace header's **View PR** button has a dropdown with **Open in GitHub**, so you can jump straight to the pull request on GitHub.
- `copy_files` entries ending in `/`, such as `node_modules/` or `target/`, copy the whole directory, so new workspaces start with dependencies already installed. On macOS the files are APFS clones: fast, with no extra disk space until files change.
- Find in the agent chat: press ⌘F (Ctrl+F on Linux) in the chat to search your messages and the agent's replies. Enter and Shift+Enter (or ⌘G and ⇧⌘G) step through matches, Escape closes.
- `recur config get`, `set` and `list` read and change Recur's settings (model, effort, permissions and more) from the terminal, whether or not Recur is running, so scripts and benchmarks no longer need the Settings window. See [Settings from the terminal](/getting-started/install#settings-from-the-terminal).
- `/address-review` fixes or answers a pull request's unresolved review comments, replies on each thread, and resolves the ones it fixed. Only comments from people with write access and review bots count.
- **Automatic fixes** under **Settings → Pull requests**: Recur resolves merge conflicts, fixes failing checks and addresses new review comments on your PRs by itself, in each PR's workspace, while its chat is idle. Each can be turned off.
- Gruvbox app theme (dark), paired with the Gruvbox Dark Medium editor theme.
- Arch Linux package (`.pkg.tar.zst`) built alongside the `.deb` and `.rpm`; install with `pacman -U`.

### Changed

- Loops are now called Workflows: the fifth chat mode is **Autopilot** and runs a workflow, and **Settings → Loops** is now **Settings → Workflows**. Bundle authors write `[[workflow]]` and `mode = "autopilot"`; existing bundles with `[[loop]]` and `mode = "loop"` keep working.
- Agent mode chats can file findings, so a review asked for in Agent mode lands in the Findings panel.
- Project dropdowns (new workspace, schedules, Inbox, Issues, Pull requests) show each project's icon next to its name.
- Claude Code chats start answering sooner: Recur snapshots the worktree for the turn's diff while Claude Code starts up instead of before launching it.
- Reviewers no longer re-raise findings you ignored or marked invalid, and a re-review resolves open findings it verifies are fixed. Add a `## Reviews` section to a repository's `AGENTS.md` to tell reviewers what not to flag.
- Cursor agents run on Cursor SDK 1.3.1 (was 1.0.38). Existing installs show an **Update** button in Settings > Providers > Cursor.
- The schedule editor's time zone list comes from the system's time zone database. Linux packages now depend on `tzdata`.
- Schedules and times shown in a chosen time zone follow the system's time zone database, so daylight-saving rule changes arrive with OS updates.
- `recur-cli` reads `bundles-dir` from `~/.recur/config.*` as a plain `key: value` line. JSON-style config files are no longer read.
- Bare URLs in hover and completion docs are clickable links, and bold, italic, code and links keep their styling inside list items.
- Downloads and in-app updates come from [celestiaorg/recur releases](https://github.com/celestiaorg/recur/releases) instead of `recur-releases`.

### Fixed

- Squash-merging a workspace without a PR now gets a summary written by the agent, the same way a PR title is written, and follows the project's Conventional Commits setting. Before, the subject was the workspace's name, and for a workspace started from a prompt action such as **Review & fix** it was the full prompt. If generation fails, the workspace's name is used, including a name you gave it later.
- Recur no longer uses CPU while idle with a chat's message box focused: its blinking caret redraws only when it blinks, not 20 times a second.
- **Resolve conflicts** on a GitHub pull request now pushes the resolved branch to the PR, the way **Fix checks** does, so GitHub sees the conflicts are gone. After a rebase the agent force-pushes with lease.
- Clicking a sidebar workspace's remove button a second time no longer gets ignored when you click quickly. If removing would lose work, the button stays armed and shows what would be lost before you confirm again.
- Agents, terminals and git no longer fail with "Too many open files" after Recur has been open a while with many workspaces.
- Follow-ups sent to a Claude agent that is waiting on a long background task (a training run, a build) keep reaching it right away while you keep talking to it, instead of waiting for the task to finish once the agent had been waiting 10 minutes.
- Dragging a text selection past the edge of a code block scrolls the block, so long lines and tall blocks can be selected in full.
- A workspace linked to a GitHub issue no longer shows an empty box beside **View #…** in the header that squeezed the workspace title.
- When a workflow asks you a question or stops on a usage limit or another temporary error, its notification and Inbox row open that workflow's chat (with several workflows in one workspace, each question gets its own row), and **Retry** on the error card resumes the workflow from where it stopped instead of re-sending your last message as a plain chat turn. If you switched the workflow's models to another provider in Settings first, the retried workflow starts fresh sessions on the new provider instead of failing to resume the old ones.
- After a relaunch, the restored workspace's chat composer has focus, so you can start typing without clicking it first.
- Recur no longer pauses for a moment right after launch when the restored chat shows tool calls with file icons.
- Recur stays responsive while a very long agent turn (thousands of steps) streams into a chat and right after it ends. Before, the app slowed down as the turn grew and could freeze for seconds, delaying new tabs and sends in other chats.
- `/re-review` on a Local PR, in the same tab as the earlier review, reviews only what changed since that pass.
- Typing past the right edge of a text field (Settings, path fields and others) scrolls smoothly instead of showing doubled, jumping text, and pasting a long value scrolls to its end right away.
- Files with spaces in their names can be dropped into chat as file mentions, including files outside the workspace such as Downloads.
- Claude agents can no longer report findings through Claude Code's own findings tool, which never reached Recur's Findings panel.
- An agent's closing message stands on its own instead of reading as a continuation of text hidden between tool calls.
- Chats on OpenAI-compatible and ChatGPT providers no longer fail when a tool returns no output, such as reading an empty file.

### Security

- API keys and other credentials (Cursor, Codex, Linear, bundle settings, compatible provider keys and headers, MCP server headers and env) are kept in the macOS Keychain or the Linux Secret Service keyring instead of in `recur.db`. Existing keys move there the first time Recur opens, and are wiped from the database. On Linux without `secret-tool`, they go to a `secrets.json` file only you can read.

## [0.6.0](https://github.com/celestiaorg/recur/releases/tag/v0.6.0) - 2026-11-05

### Added

- **File → Import Conductor Workspaces…** adopts Conductor's worktrees in place and brings their chats over as Recur chat tabs.

- A **Conventional Commits** project setting: `/commit`, `/commit-push`, `/open-pr`, generated commit messages, and PR titles use `type(scope): summary`. It is saved in `.recur/project.toml`, so it applies to everyone on the repo.

- The workspace context menu opens at the pointer near the window edges.

- The PR dock no longer jumps back to the Loop conductor tab after you pick another chat.
- Restored terminal tabs no longer inherit mouse tracking, bracketed paste, or cursor modes from the program that was running before.
- The file explorer's rename field is styled like other text inputs.

## [0.1.0](https://github.com/celestiaorg/recur/releases/tag/v0.1.0) - 2026-10-07

First release, for macOS.

### Added

- Workspaces that give each task its own branch and worktree, or work in your main checkout.
- Chats with five modes: Ask, Plan, Agent, Review, and Loop.
- Loop mode: specialist agents plan, build, and review until the work clears your bar.
- Review with findings, and checkpoints to inspect, rewind, or fork any turn.
